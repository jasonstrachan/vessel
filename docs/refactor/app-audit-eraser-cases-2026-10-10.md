## Original source-review leads (baseline findings)

### L01 — layer lock does not appear to protect erasing

`src/hooks/canvas/handlers/strokeStartLayerGuards.ts` checks visibility and adjustment-layer restrictions, but never `activeLayer.locked`. A search for runtime reads of `.locked` throughout `src` found layer-lock consumers in serialization, collaboration and LayersPanel; none in the local canvas drawing/erasing path. `src/stores/layers/layerCaptureActions.ts` also lacks a layer-lock check. LayersPanel exposes a real **Lock layer** action.

Reproduce by seeding a known raster layer, locking it through its layer menu, and erasing a held stroke. Expect unchanged pixels and no edit-history entry. Repeat CC and sequence. A guard repair should happen before authoring mutates the CC mask, rather than compensating at capture. Adjacent paint/fill/selection protection belongs to their audited areas unless the shared owner directly requires it.

### L02 — underlying CC brush can reject eraser on a raster layer

`src/hooks/canvas/handlers/strokeStartPrelude.ts` computes color-cycle flags from `tools.brushSettings` irrespective of `currentTool`. `strokeStartLayerGuards.ts` rejects `isAnyColorCycleBrush && !canUseColorCycleBrush` before reaching the later eraser exemption for regular brushes on CC layers.

Reproduce: select Color Cycle Stroke, select a normal raster layer, select Eraser, then erase. Expected: eraser works on the raster target. Source suggests rejection with the CC-layer compatibility notification. Also test entering eraser from each CC preset, including held E. Do not change valid restrictions on actual CC painting.

### L03 — Dither Grad/Shape Pattern can swallow eraser controls

`src/components/toolbar/BrushControls.tsx` defines `isShapeFillBrush` and `isDitherGradient` from `brushSettings`, whereas `activeSettings` already selects eraser settings when erasing. The corresponding early returns render gradient/shape controls before reaching EraserTipControls.

Reproduce: choose Dither Grad or Shape Pattern, then E. Expected: Square/Round/Diamond5 and eraser size/opacity controls. Source suggests the previous brush's settings panel remains. Check controls after both toolbar and keyboard tool changes. Preserve unrelated dirty work; the mixed keyboard hunks are identified in the handover.

### L04 — CC mask strategy bypasses several exposed settings

`src/hooks/canvas/handlers/colorCycle/colorCycleEraserSettings.ts` returns only size, pressure enable/range, and sanitized tip. `src/tools/EraserTool.ts` constructs no BrushStampSource for CC. `src/tools/strategies/CCMaskEraseStrategy.ts` interpolates direct stamps with hardcoded step `max(1, size * 0.45)`.

Consequently, source does not consume eraser spacing/velocity spacing, dashed length/gap/velocity, grid snap, rotation, lost edge, Riso or dither controls on the CC path. These controls are reachable in the general eraser panel, although dither visibility varies with the underlying preset's capabilities. Prove each meaningful control with matching pixel/mask comparisons before choosing whether to implement support or expose the actual supported contract. A UI-only hide is not automatically sufficient if the intended eraser contract requires parity.

### L05 — interrupted held E can leave temporary eraser active

`src/hooks/useComprehensiveKeyboard.ts` restores the prior tool when E is released after at least 200 ms. Blur cleanup restores held P's previous tool, but does not handle temporary E refs or invoke its release callback. Visibility/pointer-leave cleanup clears pressed-key tracking without resetting temporary E either.

Reproduce: brush → hold E for at least 200 ms → blur or hide document → return without receiving E keyup. Expected: no stuck temporary eraser/session. Exercise interruption in the isolated browser; do not foreground or steal focus from the user's browser. Dispatched lifecycle events are software-path evidence and should be labeled accordingly.

### L06 — CC overlay selection clip is inconclusive

EraserTool clips the strategy-returned authoring context. For CC this is the canonical erase-mask context. CCMaskEraseStrategy also stamps a separate preview overlay without that clip. However, `seedOverlayFromActiveLayer.ts` deliberately does not seed CC overlay pixels, and CC capture does not overwrite canonical raster pixels. **Do not classify this as data loss or patch it on source inspection alone.** Test visible preview/final parity across a selection boundary; canonical mask clipping already has a plausible correct path.

## Reachable controls and API-only behavior

Default eraser panel exposes:

- **Square**, **Round**, **Diamond5** buttons.
- **Brush Size (px)** slider, 1–500; **Opacity**, 0–1; **Spacing**, 1–40.
- Velocity spacing switch `#velocity-spacing-general`.
- **Lost Edge**, 0–100; **Risograph Intensity** and conditional **Riso Hue Jitter**.
- Dither/background/spread/pigment controls conditional on underlying preset capabilities. Record actual visible controls for each selected preset rather than assuming one stable panel.
- Pressure switch `#pressure-enabled`; **Pressure minimum percent**, **Pressure maximum percent** number inputs.
- Rotation switch `#rotation-enabled` when the selected tip qualifies as a stroke brush.
- Dashed switch `#dashed-enabled`; inputs titled **Length units (×brush size)**, **Gap units (×brush size)** and **Speed gap boost strength (0 disables velocity effect)**.
- Grid switch `#grid-snap-enabled`; number input titled **Grid size in pixels**.

Shape mode is intentionally hidden for eraser. `linkSizeToBrush` has no reachable component toggle: test its default linked behavior through size controls/keyboard, and identify unlinked behavior as **API-only**. Do not claim an unavailable UI toggle was exercised. Likewise, fixture setup using store APIs is separate from exercising the functionality through visible UI or real pointer/keyboard input.

Pressure range is shared between brush/eraser through the tools slice. Fixed min=max bounds provide deterministic mouse-path checks. Synthetic pen PointerEvents validate software pressure handling only; **physical stylus pressure, tilt, device interruption and hardware acceptance remain unverified without actual hardware**.
