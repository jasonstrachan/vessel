# Goblet Mobile Performance + Single HTML Size Plan

Date: 2026-07-17

Status: implemented and reviewed; automated gates and natural mobile WebGL A/B
pass, with target-phone forced-CPU fallback acceptance still pending

## Implementation Evidence

- On the target phone with the named fixture, natural playback improved from
  6.1 FPS / 242.0 ms JS p95 / 43.3 MP backing allocation to
  42.2 FPS / 6.8 ms JS p95 / 4.2 MP. The current runtime reported
  `8/8 webgl scale 1`, so this result did not trade away player render scale.
- Browser-controlled tests confirm WebGL failure eligibility, lifecycle pause
  authority, the mobile DPR/pixel cap, three-slow-window downscaling,
  five-fast-window restoration, and the transition cooldown.
- The target-phone forced-CPU pair remains required to close the CPU fallback
  performance gate in Manual Acceptance.

## Outcome Goals

1. Make a standalone Goblet remain responsive on a coarse-pointer phone when a
   Goblet 2 brush layer cannot initialize WebGL2 and must use the CPU path.
2. Stop Goblet animation work while its document is hidden or its canvas is
   outside the viewport, without changing animation time or allowing another
   event to restart a deliberately paused loop.
3. Keep fixed-viewport backing stores within an explicit mobile pixel budget and
   remove avoidable CPU slot-path allocation.
4. Show an accurate post-export size breakdown for the actual Single HTML file
   so later size work is chosen from evidence.

The work is complete only when the same named fixture is measured before and
after on the same phone, the CPU fallback is confirmed rather than assumed,
the automated lifecycle and artifact-accounting contracts pass, and desktop
WebGL playback remains unchanged.

## Decisions

- Goblet 2 remains the only runtime in scope.
- Mobile eligibility means `matchMedia('(pointer: coarse)')` when that API is
  available. Do not use user-agent detection.
- Adaptive half-resolution is allowed only after a brush WebGL2 initialization
  attempt has failed and the player is on the CPU path.
- `vesselGobletHalfRes=true` forces `0.5`; `false` forces `1` and disables
  adaptation; an absent value allows eligible adaptation.
- Mobile fixed-mode backing stores use a maximum DPR of `2` and a maximum of
  `4_194_304` pixels. Fine-pointer viewers retain the current DPR behavior.
- `prefers-reduced-motion` is not part of this pass. Freezing an artwork changes
  playback semantics on phones and desktops and needs a separate product and
  accessibility decision.
- Single HTML is the file-size target. ZIP packaging is unchanged.
- Size percentages must describe non-overlapping serialized bytes in the final
  HTML artifact. Raw decoded buffer sizes may remain diagnostic data, but must
  not be presented as percentages of the file.

## Confirmed Current Behavior

- `public/goblet2/goblet2.js` is the hand-edited Goblet 2 runtime source.
  `public/goblet2/goblet2-inline.js` is generated by
  `scripts/build-goblet-runtime.mjs`.
- A failed brush WebGL2 initialization falls back to a full CPU fill plus
  `putImageData` on every animated frame.
- The current `renderOnce` profile covers composition and display filters, but
  not the preceding CPU layer fill or `putImageData`, and its last sample is not
  exposed through a named public diagnostic surface.
- Fixed viewport mode currently uses uncapped `devicePixelRatio` for the canvas
  backing store. Non-fixed modes do not multiply their canvas dimensions by DPR.
- Resize events immediately update every active viewer and then call
  `ensureRunning()`.
- The slot CPU path allocates a base LUT, a `Map`, and one LUT per used slot on
  every eligible frame.
- Adaptive scaling is deliberately disabled by `9a53a87ed`; the existing
  regression test locks that source expression rather than exercising the
  scaling behavior.
- Both Single HTML branches create the final `Blob` and return without creating
  a `GobletSizeReport`. The current report is created only in ZIP packaging.
- The existing size fields mix serialized, base64-decoded, and inflated raw
  byte counts and therefore are not an additive artifact breakdown.
- The production export preset already sets `minifyOutput: true` and
  `embedCanvasFallback: false`. Preview generation already caps the longest edge
  at 500 pixels. No implementation work is required for those defaults.

## Non-Goals

- Display-filter resolution throttling.
- Static raster texture cropping.
- Dense typed-array replacement for per-pixel `Map.get` calls.
- Phase-map LUT allocation outside the named CPU slot path.
- ZIP format, sidecar, or runtime packaging changes.
- Goblet 1 changes.
- Saved project, CC payload, palette, flow, phase, or timing changes.
- A broad runtime architecture rewrite.
- Persistent production console logging.
- Overriding a user's persisted fallback or minification choice during export.

## Pass 1 — Mobile Runtime

### 1. Instrument the real frame path first

Add an opt-in profile mode enabled by any of:

- existing Goblet diagnostics;
- `?gobletProfile=1`;
- `localStorage.vesselGobletProfile === 'true'`.

All access to URL, storage, timing, media-query, visibility, and observer APIs
must be feature-detected and guarded because Jest/jsdom instantiates the runtime.

The profile must measure the whole active RAF frame, not only `renderOnce`:

- total active frame time;
- CPU fill time summed across players;
- `putImageData` plus half-resolution upscale time;
- Goblet composition time;
- display-filter time;
- blit time;
- observed FPS for the completed measurement window;
- WebGL and CPU player counts;
- whether WebGL initialization was attempted and why a player fell back;
- raw DPR, effective DPR, backing width/height, and backing pixel count;
- RAF state and the current pause reasons;
- current render scale and last scale-transition reason for each CPU player.

When profiling is on, keep a fixed-size numeric ring buffer and scalar counters;
do not allocate a new profile object every frame. Calculate p50/p95 and construct
objects only when diagnostics are requested.

Expose one named, read-only surface:

```js
window.__VESSEL_DUMP_GOBLET_PROFILE__()
```

It returns snapshots for active viewers and does not log automatically. Remove
the old regression assertion that bans the profile flag; replace it with
assertions that profiling is opt-in and no persistent `[goblet][profile]`
console path exists.

Before any optimization, record a ten-second warm profile from the manual
fixture below with WebGL2 deliberately unavailable. This is the baseline for the
Pass 1 stop condition.

### 2. Make RAF eligibility a single authority

Store viewer-owned state for:

- `isDocumentVisible`, initialized from `document.hidden` when available;
- `isCanvasIntersecting`, initialized `true` until an observer reports;
- `isDestroyed`;
- whether an adaptive scale transition is active.

Add one `canRunAnimation()` predicate and one `reconcileAnimationLoop()` owner.
Both `start()` and `ensureRunning()` delegate to it. Pointer guards, resize,
visibility, and intersection callbacks may request reconciliation but may not
schedule RAF directly.

The loop is eligible only when:

- the viewer is not destroyed;
- it has dynamic players;
- the document is visible;
- the canvas is intersecting;
- no scale transition is active.

Use one feature-detected `IntersectionObserver` per viewer and `entry.isIntersecting`
as the state signal. Add a feature-detected `visibilitychange` listener. Remove
the listener, disconnect the observer, cancel RAF, and remove the viewer from
`ACTIVE_CANVASES` in `destroy()`.

On resume, reset `lastTimestamp` and all adaptive measurement-window counters.
The first RAF remains a swallowed timing frame, so hidden/offscreen time cannot
become one large animation delta.

### 3. Cap coarse-pointer fixed-mode backing stores

Add constants:

```js
const MAX_MOBILE_FIXED_DPR = 2;
const MAX_MOBILE_FIXED_BACKING_PIXELS = 4_194_304;
```

For coarse-pointer fixed mode, resolve:

```text
effectiveDpr = min(
  rawDpr,
  MAX_MOBILE_FIXED_DPR,
  sqrt(MAX_MOBILE_FIXED_BACKING_PIXELS / (cssWidth * cssHeight))
)
```

Sanitize dimensions and DPR before using them. An effective DPR below `1` is
intentional when the fixed CSS surface alone exceeds the mobile pixel budget;
the backing dimensions must still be at least 1 x 1.

Persist the resolved DPR on the viewer during `updateScale()`. `renderOnce()`
must reuse that exact stored value for CSS/backing conversion, render options,
filter length scaling, clearing, and diagnostics. Do not recompute a
dimension-dependent DPR from the already-scaled backing dimensions.

Fine-pointer fixed mode and all non-fixed viewport modes retain their current
sizing behavior.

### 4. Coalesce resize bursts

Keep the existing global resize owner. Replace its immediate body with a
leading flush plus one trailing flush 150 ms after the final event:

- the first event in an idle burst updates active viewers immediately;
- intermediate events only replace the trailing timer;
- the trailing flush uses the latest viewport dimensions;
- invalid/destroyed viewers are still removed from `ACTIVE_CANVASES`;
- the final `ensureRunning()` call is safe because it delegates to the central
  RAF eligibility predicate.

Do not add one resize timer per viewer.

### 5. Remove slot-path per-frame LUT allocation

Change `buildPaletteFractionalShiftLUT256` to accept an existing 256-entry output
array while preserving its current allocate-by-default behavior for other call
sites.

During player initialization:

- allocate one reusable base fractional LUT;
- allocate one reusable `Map` from slot to LUT;
- allocate one reusable LUT for every active base-palette slot;
- clear/rebuild this cache only when initialization changes the palette, cycle
  count, or active slot set.

Each eligible slot-path frame rewrites the base and slot LUTs in place. Do not
leave the base LUT allocating while only caching the slot LUTs. Do not widen this
task to the separate phase-map branch unless the new profile disproves the named
bottleneck.

### 6. Re-enable adaptive scale with an exact state machine

Eligibility requires all of:

- brush WebGL2 initialization was attempted and failed;
- `useWebGL === false`;
- `(pointer: coarse)` matches;
- the storage preference is absent;
- the player is not destroyed or reinitializing.

An unavailable `matchMedia` means adaptation is disabled. A recolor/other CPU
path that never attempted brush WebGL2 is not an eligible fallback.

Use non-overlapping one-second windows:

- `averageFillMs = accumulatedFillMs / completedFillFrames`;
- `observedFps = completedFrames * 1000 / elapsedWindowMs`;
- slow window: `averageFillMs > 20 || observedFps < 45`;
- fast window: `averageFillMs < 12 && observedFps > 55`.

Transitions:

- at scale `1`, three consecutive slow windows request `0.5`;
- at scale `0.5`, five consecutive fast windows request `1`;
- any window that does not match the current condition resets that condition's
  counter;
- no scale transition may occur within 30 seconds of the last successful
  transition;
- pause, resume, initialization, and a successful transition reset the active
  measurement window and consecutive counters.

Make scale transition single-flight:

- while transitioning, `advance()` does not mutate animation time or render;
- CPU reinitialization explicitly skips another WebGL probe;
- preserve `baseTimeSeconds`, tick, animation flag, legacy offset, and speed;
- after successful initialization, render one frame at the preserved phase and
  reconcile the RAF loop;
- a destroy/version token prevents an awaited transition from reviving a
  destroyed player;
- handle rejection explicitly, disable further adaptation for that player, and
  surface the failure through diagnostics rather than an unhandled promise.

Do not rely only on source-string assertions. Browser behavior tests must force
WebGL2 failure and drive the one-second windows deterministically.

  restarted by pointer or resize events;

- a coarse-pointer DPR-3 fixed viewer never exceeds 4,194,304 backing pixels and
  preserves its CSS dimensions;
- fine-pointer and non-fixed viewers retain current sizing;
- one resize burst produces one leading and one trailing flush;
- the warmed slot path creates no `Map` or `Uint32Array(256)` per frame;
- WebGL and explicit half-resolution overrides never enter adaptive logic;
- eligible CPU fallback downscales after exactly three slow windows, respects
  the 30-second cooldown, and restores only after five fast windows;
- phase/time remains continuous across a successful scale transition;
- destroy during transition cannot schedule or render another frame.

## Pass 2 — Exact Single HTML Accounting

### 1. Let the HTML builder describe what it assembled

Keep existing string-returning builder APIs compatible. Add an artifact-building
variant or internal result that exposes:

- final HTML string;
- exact inserted runtime bytes after runtime transformation;
- exact serialized metadata bytes;
- HTML shell/wrapper bytes as the residual;
- exact total bytes.

The bundled-runtime and legacy fallback Single HTML builders must both use the
same section contract. Section bytes must sum to the UTF-8 byte length of the
returned HTML.

### 2. Add a non-overlapping Single HTML breakdown

Keep raw decoded buffer measurements separate for diagnostics. Add an exact
artifact breakdown for Single HTML with these mutually exclusive categories:

- runtime;
- CC buffer serialized values;
- mask serialized values;
- static texture serialized values;
- sequential-frame serialized values;
- preview serialized value;
- fallback serialized value;
- other: metadata keys/scalars, HTML shell, and wrapper code not included above.

Measure each metadata value as it appears in the final minified or readable JSON
using UTF-8 `JSON.stringify(value)` bytes. The categorized metadata fields are
disjoint. Compute `otherBytes` as the exact artifact total minus runtime and all
categorized serialized payload values. Clamp only as a defensive guard and fail
tests if accounting would otherwise become negative.

The exact categories must sum to `htmlBlob.size`. `metadataBytes` may be shown as
additional context but is not another additive category because it contains the
payload values.

### 3. Produce the report on both Single HTML branches

After constructing each Single HTML artifact and before download:

- create `GobletSizeReport` with `format: 'single-html'`;
- set exact total bytes from the final Blob;
- attach the exact artifact breakdown;
- call an optional typed `onSizeReport(report)` request callback;
- then download and complete the export as today.

Move the shared report type to `gobletTypes.ts` if needed to avoid a runtime or
type import cycle between request options and the report helper. Keep the
existing `Promise<WebGLExportMetadata>` return contract unchanged; the callback
travels through the existing request spread in `exportService` without adding a
second result authority.

3. Confirm backing pixels are within budget, backgrounding and scrolling

- the same export stays at render scale `1`;
- adaptive scaling never enables;
- fixed-mode DPR remains the current raw DPR behavior;

- confirm the displayed total equals the downloaded file size;
- confirm exact category bytes sum to the total;

## Stop Conditions

Stop and update the plan before expanding scope when any of these occurs:

- the baseline phone export does not enter the brush CPU fallback;
- display filters, not CPU layer fill/backing size, dominate after DPR capping;
- a pass requires more than its listed six files;
- accurate Single HTML accounting requires changing ZIP contracts;
- adaptive reinitialization cannot preserve phase without a broader player
  lifecycle change;
- an ineffective attempt is found during live testing—remove it before trying a
  replacement.

## Deferred Follow-Ups

Only choose these after the exact Single HTML report and final phone profile
exist:

1. Reduced-resolution display-filter surfaces if filter time dominates.
2. Static raster texture cropping if serialized texture values dominate.
3. Dense typed-array slot lookup if CPU fill still dominates after DPR,
   allocation, and adaptive changes.
4. ZIP preset/runtime improvements if actual user workflow shifts away from
   Single HTML.
5. `prefers-reduced-motion` behavior after an explicit playback-semantics and
   accessibility decision.

## Definition of Done

- The opt-in profile measures the complete active frame and is inspectable on a
  phone without persistent console noise.
- RAF has one eligibility authority and remains stopped while hidden or
  offscreen regardless of resize/pointer events.
- Coarse-pointer fixed backing stores respect the DPR and pixel caps while
  desktop/non-fixed sizing remains unchanged.
- The warmed CPU slot path no longer allocates its base/slot LUT container and
  arrays per frame.
- Adaptive scaling is limited to confirmed mobile brush CPU fallback, follows
  the exact hysteresis/cooldown rules, and preserves animation phase.
- The named phone fixture meets the recorded performance gate.
- Single HTML export reports exact Blob size and a non-overlapping additive
  breakdown for both runtime assembly paths.
- The completed export UI shows accurate size data without changing ZIP/JSON
  flows.
- All focused runtime/export/modal checks, type-check, lint, and diff checks pass.
- Deferred work remains deferred unless the new measurements select it.
